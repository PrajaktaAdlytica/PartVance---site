# PartVance Brand and Design System Brief

Date: 2026-07-10  
Company: PartVance  
Domain direction: partvance.com  
Reference inputs: PartVance site content plan, Sparrow website, Stripi design-language format.

## 1. Overview

PartVance is an AI spare parts intelligence platform for factories, fleet operators, warehouses, and maintenance teams. The brand should feel like a real European industrial SaaS company: calm, operational, precise, modern, and trustworthy.

The design direction borrows Sparrow's strongest visual qualities: clean white surfaces, confident green identity, industrial simplicity, modular product cards, visible ROI proof, and approachable product storytelling. PartVance should not copy Sparrow. It should evolve that inspiration into a more premium, data-rich, risk-aware system with sharper dashboards, clearer product hierarchy, and stronger enterprise polish.

The visual system opens with a bright white canvas, a restrained green/teal brand core, and product UI mockups that look like operational command surfaces. The feeling should be: "this is software for people who manage expensive parts, downtime, suppliers, and industrial decisions."

## 2. Brand Meaning

PartVance means advancing spare parts decisions.

- Part: spare parts, MRO components, inventory, equipment dependencies.
- Vance: from advance, meaning improve, move forward, make smarter.

Brand line:
AI spare parts intelligence for industrial teams.

Expanded positioning:
PartVance helps factories, fleets, warehouses, and maintenance teams move from reactive spare parts management to predictive spare parts intelligence.

## 3. Brand Personality

### Attributes
- Precise
- Practical
- Industrial
- Calm
- Data-backed
- European
- Trustworthy
- Modern without feeling flashy

### Voice
Plain, confident, and operational. Avoid hype. The brand should sound like it understands maintenance, procurement, finance, and plant operations.

### Messaging Rules
- Lead with outcomes: less overstock, fewer stockouts, lower downtime risk.
- Tie every AI claim to a practical recommendation.
- Use industrial language, but explain it clearly.
- Show software outputs, not abstract promises.
- Keep the EU/Poland supplier angle visible.

## 4. Logo Direction

### Concept
The logo should combine a spare-part/component signal with forward motion or intelligence.

Recommended logo mark:
- A hexagonal spare-part/nut shape to signal industrial components and MRO inventory.
- A rising signal path inside the mark to communicate forecasting and predictive intelligence.
- Three connected nodes to represent the product system: Forecast, Risk, and Suppliers.
- The mark should be simple enough to work as a favicon.
- Avoid using only a lettermark; the symbol should communicate what the startup does.
- Avoid gears as the main symbol unless heavily abstracted; gear logos are common in industrial software.

### Wordmark
Text: PartVance  
Case: Title case, not all caps  
Style: clean sans-serif, medium weight, tight but readable

### Logo Lockups
- Horizontal: mark left, wordmark right
- Stacked: mark above wordmark
- Icon only: favicon, app icon, social avatar

### Favicon
Use the standalone hex spare-part intelligence mark on a white or pale mint background. At 16px, the mark may simplify visually, but the 32px and 48px favicons should clearly show the part shape and rising signal path.

## 5. Color System

- Deep green/teal identity
- Bright lime accent
- Cool off-white sections
- White canvas
- Occasional blue highlight

PartVance palette should keep the green industrial trust, but add blue for intelligence/data and amber for risk. This prevents the website from becoming a one-note green palette.

### Color Usage Rules

- Use white as the dominant surface.
- Use primary green for the main CTA and active states.
- Use lime only as a small energetic accent, never as body text.
- Use blueprint blue for Forecast/product intelligence visuals.
- Use amber for Risk states.
- Use red only for severe/critical risk.
- Avoid large green-on-green sections that reduce contrast.
- Avoid generic blue SaaS dominance; green should remain the brand anchor.

## 6. Typography

### Font Family

Recommended production font:
- Primary: Inter
- Optional premium alternative: Söhne, if licensed later
- Monospace/data: JetBrains Mono or IBM Plex Mono for tiny dashboard labels only

Why Inter:
It is clean, readable, familiar in B2B SaaS, strong in dashboards, and available without licensing friction.

- Use sentence case for headings.
- Keep letter spacing at 0.
- Use tabular numbers for metrics, tables, risk scores, stock values, and percentages.
- Avoid thin display weights; industrial buyers need clarity and confidence.
- Keep line lengths around 56-72 characters for body copy.
- Use strong headings with compact supporting copy.

## 7. Layout System

### Base Grid
- Base unit: 8px
- Container max width: 1200px
- Wide container: 1320px for dense dashboard mockups
- Mobile page margin: 20px
- Tablet page margin: 32px
- Desktop page margin: 48px

### Spacing Tokens

| Token | Value | Use |
|---|---:|---|
| `space.2xs` | 4px | Icon gaps, small label gaps |
| `space.xs` | 8px | Tight inline spacing |
| `space.sm` | 12px | Button icon gap, compact stack |
| `space.md` | 16px | Card internal groups |
| `space.lg` | 24px | Card padding, form spacing |
| `space.xl` | 32px | Grid gaps, section content gap |
| `space.2xl` | 48px | Large component gap |
| `space.3xl` | 64px | Small section padding |
| `space.4xl` | 96px | Standard desktop section padding |
| `space.5xl` | 128px | Hero and major landing sections |

### Section Rhythm

- Hero: 96px top, 80px bottom desktop
- Standard section: 96px vertical desktop
- Dense product UI section: 72px vertical desktop
- Mobile section: 56-72px vertical
- Between heading and body: 16px
- Between section intro and content grid: 40-48px
- Card grid gap: 24px desktop, 16px mobile

### Grid Patterns

- Homepage hero: 2-column layout on desktop, text left and product UI right.
- Product pages: 45/55 split for copy and dashboard.
- Feature grids: 3-up desktop, 2-up tablet, 1-up mobile.
- Use case cards: 5 cards in responsive grid, with first card optionally larger.
- FAQ: 2-column desktop or single-column accordion mobile.

## 8. Shape, Radius, and Borders

### Radius Tokens

| Token | Value | Use |
|---|---:|---|
| `radius.xs` | 4px | Tags, small UI pills |
| `radius.sm` | 6px | Inputs, chips |
| `radius.md` | 8px | Cards, modals, product panels |
| `radius.full` | 9999px | CTA buttons, status pills |

Rules:
- Cards should use 8px radius.
- Inputs should use 6px radius.
- CTAs may be pill-shaped.
- Avoid overly rounded decorative cards.

### Borders
- Default card border: 1px solid `colors.hairline`
- Strong input border: 1px solid `colors.hairline-strong`
- Dark UI separators: rgba(255,255,255,0.12)

## 9. Elevation and Depth

PartVance should feel crisp, not floaty.

| Token | Shadow |
|---|---|
| `shadow.card` | `0 1px 2px rgba(16, 35, 31, 0.06)` |
| `shadow.panel` | `0 12px 32px rgba(16, 35, 31, 0.10)` |
| `shadow.hero-ui` | `0 24px 80px rgba(0, 63, 52, 0.18)` |

Rules:
- Use shadows mainly for product mockups and dropdowns.
- Standard cards should rely more on border and spacing.
- Avoid glow effects, orbs, and heavy gradients.

Use lucide-style line icons.

Recommended icons:
- BarChart3 for Forecast
- ShieldAlert for Risk
- Network or SearchCheck for Suppliers
- Factory for manufacturing
- Truck for fleet
- Warehouse for warehouses
- Wrench for maintenance
- Database for integrations
- ArrowRight for CTAs
- CheckCircle for proof points
- AlertTriangle for risk

Icon rules:
- Stroke width: 1.75-2px
- Icon container: 36px or 40px
- Use green, blue, or amber according to the module.
- Do not use generic AI sparkle icons as primary product symbols.

## 13. Page Design Direction

### Home
Hero should be immediate and concrete.

Recommended structure:
- Header
- Hero with product UI mockup
- Trusted/industry proof strip
- Problem cards
- Product suite cards
- How it works
- Use cases
- ROI metrics
- Integrations
- FAQs
- Final CTA

Hero visual:
Use a dashboard composition showing three visible cards:
- Forecast recommendation
- Risk alert
- Supplier reliability score

### Products
Use a data-layer diagram:
- Existing systems on left
- PartVance intelligence layer center
- Forecast, Risk, Suppliers on right

Avoid a generic SaaS feature grid. Make the architecture understandable.

### Forecast
Lead with intermittent demand and stock policy recommendations. Use blue module accents.

### Risk
Lead with criticality, downtime exposure, and mitigation. Use amber carefully.

### Suppliers
Lead with EU/Poland supplier discovery, qualification, and monitoring. Use green and network visuals.

### Use Cases
Use persona-based sections:
- Manufacturing plants
- Fleet operators
- Warehouses
- Maintenance teams
- Procurement teams

### Integrations
Make this page reassuring. It should reduce fear about ERP replacement.

### Request Demo
Keep it short, high-trust, and operational. Include fields that help qualify the pilot.

### Sign In
Should look real and complete. Use a quiet product preview next to the login panel.

Primary visual asset type:
Product UI mockups.

Secondary visual asset type:

- warehouse shelves

Photography rules:
- Bright, realistic, inspection-friendly

## 16. Responsive Rules

Breakpoints:
- Mobile: < 768px
- Tablet: 768-1023px
- Desktop: 1024-1439px
- Wide: >= 1440px

Mobile:
- Hero stacks with text first, UI below
- H1: 40px
- Section headings: 30-34px
- Cards: 1 column
- Product UI mockups crop to one key panel
- Nav becomes drawer
- CTAs become full-width only when needed

Tablet:
- 2-column cards
- Product UI can remain wide but simplified

Desktop:
- Full dashboard compositions
- 3-column product cards
- Full nav

## 17. Accessibility Rules

- Body text contrast must meet WCAG AA.
- Do not place lime text on white.
- Do not rely on color alone for risk states; pair color with label and icon.
- Buttons must have visible focus states.
- Form errors must include text.
- Interactive targets should be at least 44px high on mobile.
- Tables need readable row spacing and sticky headers when dense.

## 18. Motion

Motion should feel operational and calm.

Use:
- Small hover lifts on cards
- Button color transitions
- Accordion open/close for FAQs
- Dashboard number count-up only if subtle
- Product tabs with quick fade/slide

Avoid:
- Bouncy motion
- Excessive scroll animations
- Autoplay carousels for critical content
- Motion that hides key product information

## 19. Content and Copy Rules

Headline style:
- Short, direct, outcome-led.

Examples:
- Stop overstocking spare parts. Stop missing them during breakdowns.
- Forecast the parts that do not move like normal inventory.
- Know which parts put uptime at risk.
- Find reliable suppliers before emergencies begin.

CTA language:
- Request demo
- Explore Forecast
- View Risk dashboard
- Find suppliers
- Plan a pilot

Avoid:
- Transform your business with AI
- Unlock digital transformation
- Revolutionary platform
- Seamless end-to-end ecosystem
